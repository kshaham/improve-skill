# Token-efficient data for the agent: research, decision, and plan

Date: 2026-11-08. Scope: every place the `/improve` skill hands structured data to a model
during a run, and whether a format other than JSON would save tokens without losing
accuracy.

## 1. Where JSON reaches the model today

The cycle prompt itself is prose plus three text briefs (learning guidance, graph brief,
recovery brief). JSON reaches the model through what the agent reads during a cycle:

| Source | Shape | How often per cycle | Today |
| --- | --- | --- | --- |
| `.improve/backlog.jsonl` read directly (SKILL.md: "read run.json, backlog.jsonl ... at the start of every cycle"; `references/ledger.md` jq recipes) | hundreds of uniform rows with long `claim`/`evidence`/`failure` strings | every cycle, often several times | raw JSONL, keys repeated on every row |
| `improve_control.py pending` | array of request objects | before each item and after each settled item | one-line JSON |
| `improve_graph.py context` | nested buckets of uniform node rows | before each task | text (`print_context`) or `--json` |
| `improve_graph.py search/node/history/hotspots/path/proposals/stats/note/rate/link/restore/consolidate/unlink/sync/refine/dream` | arrays of uniform node rows or small reports | several per cycle | **pretty JSON, `indent=2`** |
| `improve_learning.py lesson` | one small object | occasional | one-line JSON |
| `improve-clock.sh --json`, `--status --json` | one small object | every cycle (clock) | one-line JSON; tiny |
| `discovery.jsonl`, `run.json`, `intake.json`, `supervisor.json` read directly | one object or uniform rows | every cycle | raw JSON |

Writes the agent makes (ledger rows, `run.json`) stay JSON: the board, the supervisor, the
graph ingestion, and the tests all parse them, and every format study agrees that
compact structured notations are for model *input*, not for model *output*.

## 2. Candidates

| Format | License and source | Python | Strength | Weakness |
| --- | --- | --- | --- | --- |
| **TOON** (Token-Oriented Object Notation), spec 4.4 | MIT; `github.com/toon-format/spec`, reference TypeScript `toon-format/toon`, official `toon-format` on PyPI (MIT, Python 3.10+), community `python-toon` (MIT, 3.8+) | yes | Declares array length and field list once, then one delimited row per element: 30-60% fewer tokens than pretty JSON on uniform arrays, within 5-10% of CSV, while keeping nesting, types, quoting rules, and an official 564-case conformance suite | Loses to compact JSON on deeply nested or non-uniform data; some independent retrieval benchmarks show lower accuracy than Markdown tables or YAML; needs a one-line syntax hint in the prompt |
| **TRON** (Token Reduced Object Notation) | MIT; `tron-format.github.io`, `tron-format/tron-javascript` | no | JSON superset with class definitions that dedupe property names; up to 27% savings in one agentic benchmark versus TOON's 18% on nested data | No Python implementation, no public conformance fixtures, less readable, results model-dependent, and the class-definition prelude costs tokens on small outputs |
| CSV | n/a | stdlib | Cheapest on flat tables | No nesting, no types, no explicit length, ambiguous empties |
| YAML | n/a | needs PyYAML | Readable, good accuracy in some studies | More tokens than TOON (keys repeated per row); not stdlib |
| Markdown tables / Markdown-KV | n/a | stdlib | Best accuracy in one retrieval study | 17% (table) to 140% (KV) more tokens than TOON; no nesting |
| Compact JSON | n/a | stdlib | Universal | Baseline; keys repeated on every row |

## 3. Determination

**Adopt TOON 4.4 for every structured output the helper CLIs print for the agent, and add
a ledger CLI that renders the backlog and discovery ledgers as TOON tables so the agent
stops reading raw JSONL.** Storage formats, the board API, and the supervisor's own files
stay JSON.

Why TOON and not TRON or CSV: the agent-facing data here is almost entirely uniform rows
(tasks, requests, graph nodes, history entries, cycle history), which is TOON's sweet
spot; TOON has a normative spec and a conformance suite that a standard-library
implementation can be proven against; CSV cannot carry the nested fields (`measurement`,
`graph_refs`, `user_notes`) or distinguish `null` from `""`; TRON has no Python
implementation, no fixtures, and its savings come on shapes this codebase does not emit.

Why not the PyPI package: the skill is standard-library only and supports Python 3.9+
(`toon-format` needs 3.10+ and would be the project's first dependency). The spec is
short and MIT; a conformant encoder and decoder is a few hundred lines and is verified
against the official fixtures vendored under `tests/fixtures/toon/`.

Accuracy risk and mitigation: the agent is a frontier model reading short tool outputs,
not a small model answering retrieval quizzes over 50 KB tables. Still: the cycle prompt
carries a one-line TOON hint, every CLI keeps `--format json`, `IMPROVE_FORMAT=json`
restores JSON globally, text fields in list views are truncated with an explicit marker
and a `--full` switch, and the decoder exists so any TOON the agent writes back (it should
not) can be read.

## 5. Results

Token counts with the `o200k_base` tokenizer (tiktoken) on representative synthetic data
built from the skill's own field names; `tests/test_toon.py` asserts the character-level
versions of the first, fourth, and small-object cases so the suite needs no tokenizer.

| Sample | JSON tokens | TOON tokens | Saved |
| --- | ---: | ---: | ---: |
| `backlog.jsonl`, 40 rows, read raw | 7,958 | 4,977 | 37.5% |
| Ledger `queue` view of the same backlog (ready rows, compact columns, width 100) | 2,744 | 777 | 71.7% |
| `improve_control.py pending`, 6 requests | 784 | 502 | 36.0% |
| `improve_graph.py search`, 15 hits (was `indent=2` JSON) | 1,687 | 897 | 46.8% |
| same versus compact JSON | 1,476 | 897 | 39.2% |
| `improve_graph.py context --json`, typical | 1,569 | 821 | 47.7% |
| `improve_graph.py history`, 20 rows (was `indent=2` JSON) | 2,502 | 1,394 | 44.3% |
| Ledger `queue` view, tab delimiter | 2,744 | 748 | 72.7% |
| Ledger `queue` view, pipe delimiter | 2,744 | 781 | 71.5% |

The largest saving is not the notation but the view: an agent that reads the ranked
queue through the ledger helper instead of the raw file spends a quarter of the tokens,
and the notation then removes another third from everything else it reads. Delimiter
choice moves the result by about one percent; the default stays comma.

Conformance: all 564 official fixtures pass (encode byte-exact, decode values and errors,
strict and lenient options, indent sizes, delimiters).

Issues found and fixed along the way:

- `tests/test_control.py` and `tests/test_graph*.py` parsed helper output as JSON; they now
  decode TOON, so the default path the agent uses is the path the tests exercise.
- The supervisor's `block_active_item` previously appended rows; `improve_ledger.py set`
  gives the agent the same canonical atomic rewrite, so both writers now keep one row per id.
- Six spec corner cases surfaced by the fixtures were fixed before integration: regex
  anchors that let a trailing newline through `$`, trimmed field names in headers, quoted
  empty field names, and blank lines between a header and its first row.

Test results: fast suite 378 tests (12 slow skipped) passing; slow suites 12 tests passing.
